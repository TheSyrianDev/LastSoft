One goal, a team that works it

You talk to the assistant. Bigger work it hands to a department: a named group of workers with a lead. The lead splits the goal into steps, gives each step to a worker, and checks what comes back. The rest of the product — memory, tools, spend — sits around that loop, and everything below runs on your own machine.

  1. The lead plans

    The lead breaks the goal into steps, one per worker, with the files and results each step needs. You approve the plan, edit it, or set the autonomy so it goes ahead on its own and reports at milestones.

  2. Workers run together

    Steps that do not depend on each other run at the same time, up to a limit you choose, each on its own model or a shared one. Steps on the same model are grouped so nothing is loaded twice for nothing.

  3. Results come back checked

    The lead reads each result against its step. Small misses it fixes in place; a real failure is retried, moved to another model, done by the lead itself, or handed to another worker. What is still unresolved reaches you with everything that was tried.

Nested

A department can hold sub-departments. A sub-department is a step that runs its own plan with its own lead, and its failure comes back as a failed step — so the same checks apply at every depth, and a stuck team cannot loop or run up cost unnoticed.

Extended

A department is a Markdown file: name, lead, members, instructions. A worker is one too, with its model, tools and memory slice. Write them by hand, edit them in the app, or share a folder of them as a plugin. Skills and MCP servers add procedures and tools under the same permission rules.

The studio, and the three parts under it

  1. P-01

    Last AI

    The studio. A desktop app and a terminal client (la) speaking to a small local core (lastaid) over localhost. The core holds the team of departments and workers, the tools, memory and learning. Any OpenAI-compatible server or local runtime will do.

    0.1.0-alpha.1
  2. P-02

    LastHarness

    The harness underneath: the core, the clients, memory as Markdown you can read, tools behind permission rules, the provider layer, the spend limits. Give it a model and a goal and it runs the turn loop. No downloader, no inference engine.

    inside Last AI
  3. P-03

    LastEngine

    Inference of its own. One backend trait, several implementations — CUDA, CPU, Vulkan, ROCm, Metal — chosen at startup by probing the hardware, with layers split across CPU and GPU for small cards.

    in development
  4. P-04

    hf-dl

    Models and datasets from the Hugging Face Hub, with resumable and verified transfers. It is just a downloader, and it works alone.

    v0.4.0-rc.1

Three things it will not do

Sign you in
There is no account, no telemetry endpoint, no billing behind a key. Model calls go to the server you named, with the key you gave.
Rewrite your prompt
Learned rules, style and skills are separate blocks added after the base prompt. Every version is kept, and anything applied without asking is logged so you can undo it.
Hold your keys in a file
Secrets live in the OS store — Secret Service, Keychain, Credential Manager. The config holds a reference like secret:openrouter, never the value.

Get it

Prebuilt for Linux, Windows and macOS, with a script for Linux that works out which distribution you are on before it installs anything.
