Part LAI · 0.1.0-alpha.3

Last AI

A local-first AI studio for one person's computer. A desktop app and a terminal client in front of a small core that keeps the conversation, the memory, the tools, the money and the team of workers.

Alpha. Tested on Linux (Omarchy) and Windows; the macOS build starts in CI but nobody has used it day to day. Expect breaking changes.

Three programs

lastaidThe core. Holds state, listens on 127.0.0.1:7842 only.
lai / lastaiThe terminal client, one program under two names.
lastai-guiThe desktop app. Finds the core and its token by itself.

The clients are thin: everything they show comes from the core over localhost. Stop the core and the app has nothing to talk to.

Install

Prebuilt packages are attached to each GitHub release: .deb, .rpm, an Arch package, an AppImage, a Windows zip, and an unsigned macOS .app in a zip. On Linux, the download page's script works out your distribution first.

From source, with Rust stable:

cargo build --release                     # all four binaries
cargo build --release -p lh-core -p lh-tui  # just the core and terminal

First run

lai setup        # twelve questions; Enter accepts each default
lastaid         # start the core (reads config.toml)
lai              # chat
lastai-gui      # or the desktop app, with the core running

To keep the core alive across logins: lh service preview, then lh service install. That writes a systemd user service — no sudo — so closing the terminal never stops the core.

Providers and models

A provider is a server that answers chat: llama-swap, llama.cpp, Ollama, LM Studio, any OpenAI-compatible endpoint, or an Anthropic-style cloud API. Add and test them on the Models and keys page, or with lh settings. API keys are read from environment variables you name. Nothing is sent to a provider you have not added.

The same page searches Hugging Face for GGUF files and groups the results by whether they fit this machine's memory — Fits in memory, Tight, Too big, Size not known — then downloads into ~/AI/Models/. A model your llama-swap router does not serve yet gets a Run button that backs up the router files, validates the matrix and restarts the router. Models already served show Use in chat.

The Create block on the same page makes images (Z-Image Turbo) and short videos (Wan 2.2 TI2V-5B) through a local ComfyUI on 127.0.0.1:8188, saving into ~/AI/Create/. Image and video jobs take the machine lock and free GPU memory when done, so they wait while another session holds it. ComfyUI and its weights are not part of the repository.

Memory, learning, and the team

  • Memory is Markdown notes under ~/.local/share/lastai/memory/. Read them, edit them, delete them — the core treats files as truth.
  • Learning produces rules, style notes and skills. Each one waits for approval; what gets applied without asking is logged so you can undo it.
  • Team is departments of role workers, each a Markdown file: lead, members, model, tools, memory slice. Give a department a goal with lh team run and its lead plans, its workers run in parallel up to your limit, and the lead checks each result before you see it. Departments nest; a sub-department is a step whose failure comes back as a failed step.
  • Permissions are tiered: reads are free, writes ask once, anything risky always asks. Sensitive notes and rules are only ever used with a model on this machine.

Commands worth knowing

lh setupFirst-run questions.
lh settingsSee and change every setting (set, reset).
lh memoryThe notes the assistant keeps.
lh learnRules, style, skills, suggestions waiting for you.
lh teamRoles, model types, departments, goals, workers, away mode, plugin folders.
lh mcpMCP servers. Nothing runs until you approve it.
lh trust <folder>Which project folders may bring their own MCP servers.
lh devicesPair a browser with a PIN, list, remove.
lh channelsTelegram, Matrix, Slack, Signal — off until switched on.
lh export / lh importMove memory, rules, style, roles and departments.
lh serviceStart the core at login.

Every command has help, and it works with the core stopped: lh team help.

Where files live

~/.config/lastai/config.tomlSettings. Optional spend.toml beside it for prices.
~/.local/share/lastai/lh.db (activity log, rules, indexes), memory/, skills/, team/, mcp.json, web/.
$XDG_RUNTIME_DIR/lastai/tokenThe token the clients need. Not in your home directory.
~/.config/lastai/themes/Looks: one folder per look, a theme.toml, optionally background.png.

What is not there yet

  • A phone app, and any final visual design (no logo or brand colours inside the app).
  • Signed installers and updates; crash reports are prepared but not sent.
  • The hosted relay, subscriptions, memory sync.
  • Agents loading and unloading local models on their own — they can list models, pick one among your providers, and propose a new provider for you to approve.
  • Installing a plugin from a link (folders only), and project-level skills.
  • Messaging channels tested against real accounts; they run against mocks.
