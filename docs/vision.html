The vision

The last AI you'll need

The end state is not a bigger product. It is a computer that runs capable AI for one person: their work, their notes, their files, their projects, with every part that makes it work owned by that person and nothing rented by the minute.

The whole stack, on your desk

Today the studio borrows both ends of the stack: models are fetched with someone else's tool and inference runs in someone else's engine. The finished picture has all four parts your own: the downloader pulls the weights, the engine runs them, the harness runs the turns, the studio is where you work. Four repositories, one install, no service in the middle.

ThenNow
A model is a file on your disk that the engine you shipped knows how to run.Model-Downloader fetches it; a llama.cpp-family server you already run serves it.
The engine that ships with the studio is the same engine in the repository, on CUDA, Vulkan and Metal.LastEngine runs its own server on NVIDIA hardware, measured on one card.
A department of workers plans a real goal over your files and finishes it while you are away.The team loop exists; autonomy stops at approvals you set.
Everything you taught it survives a new machine in one folder you can copy.Memory, rules, roles and departments export and import.
One install works on Linux, Windows and macOS, signed and updated honestly.Linux and Windows are tested; macOS is early alpha; nothing is signed.

Five things that will stay true

  1. Your machine does the work. Loopback is the bus. The only network calls are the ones a request you made implies: a provider you added, a download you started, a search you asked for.
  2. No account, ever. Not a free one you signed into, not a key you cannot see, not a sync you cannot turn off. If a feature needs a server, it says so before you enable it.
  3. The parts stand alone. Somebody should be able to use Model-Downloader and never hear of the studio; somebody should run the harness against their own server and never run the engine. A bundle that only works as a bundle is a lock, and this is not that.
  4. You can read what it knows. Memory is Markdown, roles are Markdown, looks are a folder with a TOML file. Anything the machine concluded about you is a file you can open, edit, or delete, and the index rebuilds from the files, not the other way round.
  5. Honest about the state. Every README names the version and the gaps. No benchmarks we did not run, no screenshots we did not take, no "production ready" on alphaware.

How work changes when the assistant is local

The interesting shift is not that the model runs near you. It is that the assistant can hold the whole of your work: the repository, the notes, the half-finished design, the three-month-old decision, the machine's actual memory ceiling. A hosted assistant sees what you paste. A local one can be given a folder and a permission rule.

So the studio is built around a team rather than a chat box: a goal goes to a department, a plan comes back, workers run, results are checked, and you get the outcome with the attempts attached. The model stops being an oracle you consult and becomes a colleague with a desk in your machine, one that forgets nothing you told it to keep and does nothing you did not allow.

What "done" looks like

  • One command on a clean machine installs the studio, and it starts at login without root.
  • A model is downloaded, verified, registered and answering, all from inside the app.
  • A department finishes a multi-step goal over a real folder, unattended, inside the spend and permission limits you set.
  • The same memory, rules and team move to a new laptop by copying one directory.
  • Nothing in the UI requires a login, a telemetry ping, or an internet connection that you did not ask for.
  • The three engines (CUDA, Vulkan, Metal), each measured, each with numbers in the repository.

What it will never be

  • A hosted service with a subscription in front of it.
  • A wrapper that forwards your files to an API and calls it local.
  • A platform with a plugin store, an account tier, or a growth loop.
  • Closed. Source-available now, and the permissive bits (hfd-core) stay permissive.

One developer, in the open, pre-release. The vision is the direction of travel, not a shipping promise; the version on each page is what exists today.
