The Last AI suite

Four programs written in Rust for one person's computer: an assistant, the harness under it, an inference engine, and a downloader. They fit together as Last AI. Each one also works with nothing else from the family.

The four parts

PartWhat it isState
Last AI The studio. Desktop app and terminal client over a local core: conversations, memory, tools, a team of departments and workers, spend limits. 0.1.0-alpha.3
LastHarness The turn loop and everything around it — providers, tools with permissions, memory, team, MCP. No UI of its own, no downloader, no engine. inside Last AI
LastEngine Inference. One backend trait, several implementations, a hardware probe that decides what this machine can actually run. 0.1.0, in development
hf-dl A Hugging Face downloader. Resumable, segmented, verified transfers, with a queue you can leave running. v0.4.0-rc.1

How they fit

Last AI is the only thing you are meant to install as a product. The core (lastaid) listens on 127.0.0.1 and holds the state; the desktop app, the terminal client and paired browsers are thin clients of that one HTTP API. Models arrive through hf-dl and are served either by a local runtime you already run, or — later — by LastEngine behind the same provider interface. 

desktop app   terminal (la)   paired browser   messaging channels
      \             |                |                /
       \            v                v               /
        +--------- lastaid (core: turn loop, team, tools, memory) ---------+
        |                             |                                    |
        |                             +-- permission rules -> tool calls   |
        |                             +-- spend ledger -> provider layer   |
        |                                                         |        |
        +---------------------------------------------------------+        |
                                                                          |
   provider layer: llama-swap / llama.cpp / Ollama / LM Studio / OpenAI-   |
   compatible / Anthropic-style APIs  .......... and, eventually, Last-    |
   Engine behind the same shape                                            |
                                                                          |
   models and datasets: hf-dl -> ~/AI/Models -> the runtime you point at    |

Nothing in that picture needs the network except a provider you added and a download you started.

What one turn looks like

  1. You type into the app or the terminal; the client posts to the core.
  2. The core assembles the prompt: the base prompt, then your learned rules, style and skills as separate blocks after it, then memory the task needs.
  3. The model replies. If it asks for a tool, the permission rule for that tool decides: reads are free, writes ask once, risky things always ask.
  4. Anything that costs money is written to the spend ledger, priced from spend.toml when you supplied prices.
  5. If the goal is bigger than one turn, the core hands it to a department: a lead plans, workers run the steps, the lead checks the results, and what it cannot settle comes back to you with everything that was tried.
  6. What is worth keeping becomes a note (Markdown you can read) or a rule waiting for your approval.

Quick start

# the whole studio, from source
git clone https://github.com/TheSyrianDev/LastAI
cd LastAI
cargo build --release

target/release/la setup    # twelve questions, Enter takes the default
target/release/lastaid     # the core, on 127.0.0.1:7842
target/release/la          # chat

# a model first, if you have none
cargo install --path ../hf-dl/crates/hfd-cli
hfd download Qwen/Qwen3-0.6B --include "*.gguf" --local-dir ~/AI/Models

Prebuilt packages for Linux, Windows and macOS (early alpha) are on the downloads page.

The rules the suite is built on

  • Local first. The core binds to loopback only. There is no account, no telemetry endpoint, no billing behind a key.
  • Stand-alone parts. The engine runs without the app, the harness runs against any OpenAI-compatible server, and the downloader is just a downloader.
  • Say the version. Every page and README names the release and the gaps. Pre-release means pre-release.
  • Nothing hidden in the prompt. Learned behaviour is appended in separate blocks, versioned, and applied without asking is logged.
  • Secrets stay in the OS store — Secret Service, Keychain, Credential Manager. Config holds a reference, never the value.
